# Project workflow

## Branch and publishing

- Do project work on `tharun-work`; never push this project's changes to `main`.
- After completing each requested implementation, commit the intended changes with a concise, descriptive commit message and push the commit to `origin/tharun-work`. This is the user's standing preference; do not ask for confirmation again.
- Check the current branch and worktree before editing. Preserve unrelated changes and never stage credentials, `.env` files, or other secrets.
- If a push cannot complete, report the failure and leave the local commit available for retry.
